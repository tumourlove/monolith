# Monolith Wiki

**One plugin. Every Unreal domain. Zero dependencies.**

Monolith is an Unreal Engine 5.7 / 5.8 editor plugin that gives AI assistants full read/write access to your project through the [Model Context Protocol (MCP)](https://modelcontextprotocol.io). **~1,500+ actions across 27 in-tree namespaces** (counts are approximate — query `monolith_discover()` for the live figure), exposed through a small set of namespace-dispatch MCP tools. Native C++ — no Python runtime, no external dependencies, no bridge servers.

For what changed in each release, see [[Changelog]] or the [Releases page](https://github.com/tumourlove/monolith/releases).

---

## What Can It Actually Do?

Monolith can read, write, create, and modify assets across every major UE domain. Here's what each namespace covers:

### Blueprints (112 actions)
Full lifecycle management. Create Blueprints, add variables/components/functions/macros, wire up node graphs, set pin defaults, compile, and validate — all programmatically. Bulk operations let you add dozens of nodes and wire them in a single call. Auto-layout (Sugiyama algorithm) cleans up messy graphs. Interface scaffolding auto-generates stub events. CDO property reading gives you access to any UPROPERTY default on any Blueprint or UObject. Compare Blueprints, trace execution flow, search nodes across graphs. UDS, UDE, event dispatchers with full CRUD. New in 0.15.0: a **dataset read/edit pack** for round-tripping DataTables, CurveTables, and StringTables (read with the row struct schema inline, bulk upsert with dry-run previews, row CRUD, JSON/CSV import/export), plus `seed_data_asset` (create + populate a DataAsset in one atomic call), `add_property_access` (get/set a UPROPERTY on any foreign class by name), `override_parent_function` (override a parent function that returns a value), and `save_dirty_assets`. **New in v0.19.0:** `find_variable_references` (every node that reads or writes a member variable, with read/write classification) and variable-contract reconciliation for BP→C++ nativization (`compare_class_variable_contract`, `promote_variables_to_parent`). If you can do it in the Blueprint editor, you can do it through Monolith.

### Materials (64 actions)
Create materials, material instances, and material functions from scratch. Build entire material graphs programmatically from a JSON spec — expressions, connections, properties, all in one call. Write custom HLSL nodes. Import textures from disk directly into UE assets. Full material instance lifecycle — create, set parameters (scalar/vector/texture/static switch), reparent, clear overrides, find all instances of a parent. Render previews to PNG. Validate graphs for islands, broken references, and duplicate parameters. Batch operations across multiple materials. Export/import material graphs as JSON for templating or migration.

### Animation (125 actions)
Covers the full UE animation pipeline. Sequences, montages, blend spaces, aim offsets, composites — full CRUD on all of them. Montage section management, slot configuration, blend settings. Blend space sample manipulation with skeleton validation. Animation Blueprint inspection and structural writes — read state machines, transitions, blend nodes, graphs, variables, then add states, add transitions, and set transition rules. As of 0.15.0, `add_anim_graph_node` resolves arbitrary concrete custom `UAnimGraphNode_Base` classes by path or name, not just the built-in node-type aliases. PoseSearch integration — read schemas, manage databases, add/remove sequences, get stats. IK Rig and Retargeter inspection and configuration. Control Rig hierarchy manipulation — add bones, controls, nulls. Skeleton management with socket CRUD, virtual bones, curve editing. Notify CRUD with track management. Bone track key manipulation for procedural animation. This covers the entire UE animation pipeline from raw sequences to runtime ABP logic. **New in v0.19.0:** anim-node function + pin binding read/write (`get`/`set_anim_node_function_bindings`, `get`/`set_anim_node_pin_binding(s)`) and `sample_pie_timeseries` — an async PIE session that samples dotted, UDS-friendly variables each tick and fires typed provocations (control rotation, movement input, jump, console command) on a timeline.

### Niagara VFX (129 actions)
Comprehensive particle system control. Create systems and emitters from scratch, or build complete systems from a declarative JSON spec. Full module stack management — add, remove, move, enable/disable modules with override-preserving reorder. Set any module input by value, parameter binding, or dynamic input. Dynamic input full lifecycle — search available DI scripts, attach them, configure their sub-inputs, read the tree, remove them. Event handler and simulation stage CRUD for advanced GPU workflows. Create custom Niagara modules and functions directly from HLSL source — no editor graph wiring needed. Renderer management with mesh, ribbon, and SubUV presets. Data interface configuration with JSON array/struct support. Parameter discovery and binding trace. System validation catches GPU+Light conflicts, missing materials, and bounds issues — and as of 0.15.0 it reasons about inter-emitter event chains, classifying each emitter's role and warning when a receiver consumes an event its named source never generates (PR #60 by @middle233). `get_system_summary` / `get_emitter_summary` take a `detail_level` for richer event-aware payloads. Export any system as a full JSON spec for diffing, templating, or version control. Batch operations with read optimization. Effect type management. **New in 0.17.0:** a temporal-control surface (9 actions) that collapses scattered timing edits into composite, intent-named writers — `get_system_timing` (bundled read), `set_warmup_profile` / `set_fixed_tick_delta` / `set_require_current_frame_data` (system-level), `set_emitter_loop_profile` / `get_emitter_timing_summary` (emitter loop topology + lifetime read aggregator), `set_sim_stage_iteration_count` / `set_sim_stage_execute_behavior` (sim-stage aliases), `set_particle_lifetime` (Direct/Random InitializeParticle convenience), plus `create_stateless_emitter` for standalone `UNiagaraStatelessEmitter` (Lightweight Emitter) authoring with stateless-aware branches on the two emitter composites. Phase 4a also adds `niagara_query("audit_cross_asset_refs")` — a broken/stale asset reference scan over Niagara systems/emitters joined against the new `cpp_asset_edges` table. **New in 0.18.0 (PR #65 by @middle233):** read and overwrite the HLSL source on an existing `CustomHlsl` node in place (`get_custom_hlsl_text` / `set_custom_hlsl_text`), target shared-graph simulation-stage and event scripts directly through `usage` selectors on the module-stack actions, a ParameterMap bridge with strict type validation for `create_module_from_hlsl`, plus a search & discovery pack (`search_by_parameter`, `search_by_data_interface`, `search_by_material`, `query_niagara`, `find_similar_systems`, `find_niagara_references`, `list_system_data_interfaces`).

### UI / UMG (138 actions)
Widget Blueprint CRUD with a template system that scaffolds complete, functional UI from a single call. Pre-built templates for HUDs, main menus, settings screens, dialog boxes, loading screens, inventory grids, save/load menus, and toast notifications. Styling system for consistent theming. Widget animation support (v1 + v2 hoisted core/events). Game-level scaffolding actions that generate settings, save systems, audio managers, input rebinding, and accessibility configurations. Built-in accessibility audit. The templates produce wired-up UI with proper hierarchy, bindings, and event handling. The Phase A–L architecture expansion (v0.14.0) added a schema-driven Spec system (`build_ui_from_spec` / `dump_ui_spec_schema` / `dump_ui_spec`), Type Registry with per-type property allowlist, EffectSurface widget + sub-bag setters, dedup-driven Style Service, and 51 CommonUI actions (gated on `WITH_COMMONUI`) for activatable stack management, focus, button conversion, dialogs, lists, navigation, and accessibility. 0.15.0 closed a big chunk of the MCP gap here: close-the-loop primitives (`rename_widget`, `add_widget_variable`, `audit_focus_chain`, `list_widget_property_enums`, `convert_textblock_to_common`, `dump_blueprint_compile_log` and friends), headline scaffolders (`scaffold_main_menu`, `scaffold_settings_panel_with_tabs`, `scaffold_pause_menu`, `build_menu_from_spec`), and navigation/conversion actions (`set_widget_navigation_bulk`, `dump_widget_navigation`, `convert_border_to_common`, `reparent_widget_root`, `set_widget_is_variable`). 0.25.0 adds UMG MVVM support (8 actions: read a Widget Blueprint's viewmodels and bindings, add and remove viewmodels, bindings and events, toggle FieldNotify), registered only when the UMG Viewmodel plugin is enabled in a source build. The 4 GAS UI binding actions (`bind_widget_to_attribute` etc.) are aliased into the `ui::` namespace from `MonolithGAS` when `WITH_GBA` is on.

### Mesh & Spatial (194 actions)
This is the big one. 194 core actions across 22 capability tiers (plus 45 work-in-progress town gen actions that are off by default and not in the public count), covering everything from basic mesh inspection to full procedural level design. Read any StaticMesh or SkeletalMesh — triangle counts, LODs, collision, UVs, quality analysis, side-by-side comparison. Mesh import now supports optional skeletal-mesh + animation import via `import_mesh` (PR #58 by @4698to). Scene manipulation gives you full actor CRUD — spawn, move, duplicate, delete, group, set properties. Physics-based spatial queries let you raycast, overlap test, radial sweep, navmesh path, and check line of sight — all in-editor, no play session needed.

Level blockout is where it gets interesting. Tag BlockingVolumes, drop in primitives, auto-match them to real assets from your project's mesh catalog by size, then atomically replace the blockout with production meshes. Export/import layouts as JSON for templating. Scan volumes with a "Daredevil mode" raycaster that maps walls, floors, ceilings, and openings.

GeometryScript mesh operations give you boolean, simplify, remesh, LOD generation, hole filling, UV projection, and mirroring through a handle-based workflow. Horror spatial analysis (work-in-progress — functional but still being refined) scores sightlines, finds hiding spots and ambush points, analyzes choke points and escape routes, classifies zone tension, and traces pacing curves along player paths. Accessibility analysis validates wheelchair clearance, navigation complexity, visual contrast, rest point spacing, interactive reach, and generates full accessibility reports with A-F grading — built for players with diverse accessibility needs.

Lighting analysis (work-in-progress — functional but still being refined) samples light levels, finds dark corners, flags harsh light transitions, maps coverage, and suggests placement for horror/safe room/clinical moods. Audio and acoustics (work-in-progress — functional but still being refined) cover 14 actions — surface material detection, Sabine RT60 reverb estimation, sound propagation with material-based occlusion, stealth maps, quiet path routing, and AI hearing simulation. Performance analysis (work-in-progress — functional but still being refined) gives you region budgeting, pre-spawn cost estimation, overdraw hotspot detection, shadow cost analysis, and frustum-culled triangle budgets.

Beyond that: decal placement with Catmull-Rom path following and 5 horror storytelling presets. Level design tools for lights, materials, mesh swaps, LOD thresholds, and HISM instancing. Volume spawning (trigger, kill, pain, blocking, audio, post-process). Tech art pipeline for mesh import, LOD generation, texel density analysis, collision authoring, and lightmap density checks. Advanced level design with sublevel management, prefab creation, spline placement, and filtered actor enumeration. Context-aware prop placement that scatters on surfaces (floors, shelves, tables, walls, ceilings), applies room disturbance levels, configures physics sleep states, and manages themed prop kits.

Procedural geometry generates parametric furniture (15 types from chairs to bathtubs), horror props (7 types including barricades and vent grates), architectural structures (rooms, corridors, L/T-junctions), multi-story building shells, mazes (3 algorithms), pipe networks, mesh fragmentation, and terrain patches. An extensible [[Genre Presets]] system lets you author storytelling patterns, acoustic profiles, and tension profiles for any genre — horror ships as the default, but the system is genre-agnostic. Encounter design covers spawn evaluation, patrol route suggestion, AI territory analysis, safe room scoring, level pacing structure, scare sequence generation, horror intensity validation, and full accessibility reports. Quality and polish rounds it out with naming convention checks, batch rename with reference fixup, proxy mesh generation, HLOD setup, texture budget analysis, composition framing, and monster reveal scoring.

For the full breakdown, see [[Mesh Module]] and [[Tool Reference]].

### Editor Tools (33 actions)
Trigger UBT builds and Live Coding compiles. Read build errors, compile output, and crash context. 10,000-entry log ring buffer with full-text search, category filtering, and verbosity control. Scene capture to disk. Texture import. Flipbook stitching from sprite sheets. Viewport info queries. Blank-map factory and module status queries (Phase J F8). Automation framework integration — list and run UE automation tests in-process (`list_automation_tests`, `run_automation_tests` — v0.14.8). Python escape-hatch (`run_python` — three execution modes via `IPythonScriptPlugin::ExecPythonCommandEx`) and persistent-level swap (`load_level` — single-arg map swap via `ULevelEditorSubsystem::LoadLevel`) for integration tests / automation flows (v0.14.9). **New in 0.16.0**: `capture_material_grid` (N material instances side-by-side), `capture_with_overlay` (5 engine debug-view modes — wireframe, normals, UV density, lightmap density, shader complexity), `inspect_material_pbr` (PBR parameter classification + ORM/ARM/MRA channel-packing detection — pure reflection, no rendering), `inspect_texture_channels` (per-channel R/G/B/A min/max/mean statistics + optional per-channel split PNGs). Plus `capture_scene_preview` is extended with new `asset_type` values: `static_mesh`, `skeletal_mesh` (with optional posed-frame capture via `animation_path` + `seek_time`), and `widget` (UMG via `FWidgetRenderer`). **New in v0.19.0:** live-PIE introspection and driving — read UPROPERTY values off a running PIE object (`pie_get_object_properties`), call a BlueprintCallable function on it (`pie_call_function`), set control rotation (`pie_set_control_rotation`), inject Enhanced Input action values (`pie_inject_input_action`), detach to a free-fly spectator (`pie_possess_spectator_free`), and read a stats group programmatically (`get_stat_group_values`). `get_build_errors` also gained deterministic `fix_hints[]`.

### Config / INI (6 actions)
Full config resolution — resolve any setting to its effective value, get a multi-layer breakdown showing which INI file wins, diff against engine defaults, search across all config files. Useful for debugging why a setting isn't taking effect when you've got 5 layers of INI overrides fighting each other.

### Engine Source Index (20 actions)
1M+ C++ symbols indexed natively — no Python, no external tools. Read full class source or just the member list. Search symbols across the entire engine. Traverse call graphs (callers and callees). Walk class hierarchies. Get module info. Read raw source files by path. All of this works offline against a local SQLite database, so it's fast and doesn't need network access. Optional project C++ indexing adds your own source alongside engine symbols. **New in v0.19.0:** an LLM C++ authoring ergonomics pack — `get_include_path`, `get_signature`, `check_deprecations`, `verify_symbols`, `find_example_usage`, `suggest_build_cs_deps`, `lint_header` (works on unindexed headers you just wrote), and `generate_class_stub` (returns a UCLASS `.h`/`.cpp` pair as text, never writes to disk). A parser fix that indexes allman-brace plain classes/structs tripled the symbol index (~300K → ~967K), so previously-missing engine types like `FCollisionShape`, `FScopeLock`, and `FPaths` now resolve.

### Project Index (8 actions)
FTS5 full-text search across every indexed asset in your project, including marketplace plugins. Bidirectional dependency tracing. Filter by type with pagination. Deep asset details — nodes, variables, connections. Covers 9,500+ assets out of the box with automatic indexing on editor startup.

### GAS / Gameplay Ability System (135 actions)
Complete Gameplay Ability System integration across 10 categories. Create and manage Gameplay Abilities with activation policies, cooldowns, costs, and tags. Full AttributeSet CRUD — both C++ and Blueprint-based (via optional GBA plugin). Gameplay Effect authoring with modifiers, duration policies, stacking, period, and conditional application. ASC management — grant/revoke abilities, apply/remove effects, query active state. Gameplay Tag utilities, Gameplay Cue management, target data generation, input binding for ability activation, runtime inspection and debugging tools, and scaffolding actions that generate complete GAS setups from templates. Accessibility-focused infinite-duration GEs for players with diverse needs.

### AI (221 actions)
The most comprehensive AI tooling available through any MCP server. 221 actions across 15 categories covering Behavior Trees, Blackboards, State Trees, EQS, Smart Objects, AI Controllers, AI Perception, Navigation, and runtime debugging. Crown jewel actions: `build_behavior_tree_from_spec` and `build_state_tree_from_spec` — hand the AI a JSON description and it builds the entire asset. Create BT nodes (tasks, decorators, services), wire them into trees, configure blackboard keys, set up EQS queries with generators and tests, define Smart Object slots, configure perception senses (sight, hearing, damage, touch), manage navigation filters, inspect and debug AI at runtime. Scaffolding generates complete AI setups from templates. Conditional on State Tree and Smart Objects plugins (both ship with UE). Optional Mass Entity and Zone Graph integration.

### Logic Driver (66 actions)
Full integration with Logic Driver Pro. State machine CRUD, graph read/write, node configuration, runtime/PIE control, JSON spec import/export. Crown jewel: `build_sm_from_spec` builds complete state machines from JSON. Scaffolding generates common patterns — door controllers, health systems, AI patrols, dialogue systems, elevators, puzzles, inventory. Component management, text graph visualization, discovery actions. Reflection-only integration, conditional on `#if WITH_LOGICDRIVER`.

### ComboGraph (13 actions)
Integration with the ComboGraph marketplace plugin for combo tree editing. Graph CRUD, node/edge management with montage animations, effect and cue configuration. GAS cross-integration for combo ability scaffolding. Reflection-only, conditional on `#if WITH_COMBOGRAPH`.

### Audio (98 actions)
Editor-time audio asset authoring. Full CRUD on the 5 configurable audio asset types — SoundAttenuation, SoundClass, SoundMix, SoundConcurrency, SoundSubmix. Query and search across all audio assets, with hierarchy inspection and audio health checks (missing class, no attenuation, unused sounds). Batch operations for assigning sound class/attenuation/submix/concurrency/compression/looping/virtualization across dozens of assets in one call. Sound Cue graph construction — add nodes (22 types), wire them via `ChildNodes[]`, set properties via reflection. MetaSound Builder API integration for programmatic MetaSound authoring — add nodes, connect pins by name, manage graph inputs/outputs, interfaces, variables. **MetaSound document introspection (v0.14.10, 12 actions)** — read-only walk of `IMetaSoundDocumentInterface::GetConstDocument()` for any MetaSound asset: project-wide enumeration (`list_metasounds`), full document walk (`get_metasound_document`), summary counts (`get_metasound_summary`), per-node instance details (`inspect_metasound_node_instance`), connections, variables, user parameters, search, info, dependencies, and validation. Distinct from the Builder API actions — those read live builder state during mutation; introspection reads on-disk doc state for arbitrary assets. PR #18 by community contributor @alakangas. Companion `FMetaSoundIndexer` deep indexer in MonolithIndex (also v0.14.10). Crown jewels: `build_sound_cue_from_spec` and `build_metasound_from_spec` — declarative JSON-to-graph in a single call. Five template Sound Cues (random, layered, looping ambient, distance crossfade, switch) and four template MetaSounds (oneshot SFX, looping ambient, synth tone, interactive). SoundWave is read-only — `get_sound_wave_info` for inspection, `batch_set_sound_wave_properties` for reflection-based property edits. MetaSound features gated on `WITH_METASOUND` — graceful degradation when the plugin isn't present.

### Level Sequence (8 actions)
Cinematic / sequencer asset authoring. Create level sequences, add tracks, manage shots and bindings — including UE 5.7's custom-binding awareness for the new sequencer architecture. Dedicated SQLite indexer for cross-sequence query. Shipped v0.14.8 as PR #45 by community contributor @yashabogdanoff.

### Gameplay Tags (14 actions)
Added in 0.25.0 (PR #170 by @yashabogdanoff). Finds where a tag is used from the Asset Registry, the same data the editor's "still referenced by" uses, so it covers properties, graph pins, level components and containers with no reindex. Audits for unused and broken tags, and declares, edits, renames (redirect-based), moves and removes ini tags, refusing removals while anything still uses the tag. Toggle with `bEnableGameplayTags`, independent of GAS.

### Enhanced Input (15 actions)
Added in 0.23.0. Read and author `UInputAction` and `UInputMappingContext` assets: list and inspect actions and contexts, add and remove key mappings, triggers and modifiers, validate mappings. Registered alongside GAS but works without it.

### Localization (4 actions)
Added in 0.23.0. Read-only culture discovery and StringTable inspection. Stays available when config authoring is switched off.

### Chooser (16 actions)
Chooser Table inspection and authoring: create tables, add columns and rows, set cells and result references, and validate. The six read-only actions work without the Chooser plugin; the ten authoring actions need it.

### Bulk-fill + describe ergonomics framework (`bulk_fill` 2 + `describe` 3 actions)
New in 0.15.0. A reflection-walker bulk-fill framework that lets your AI populate or inspect deeply-nested property trees in one call, with the same mental model across every domain. `bulk_fill_query` exposes `apply` (a dry-run-able tree write) and `list_namespaces`; `describe_query` exposes `schema`, `list_targets`, and `action_schema` (return any registered action's full param schema — names, types, required, defaults, aliases — so callers stop trial-and-erroring param names). Both route to 12 per-namespace adapters (blueprint, gas, ui, ai, niagara, material, audio, mesh, animation, logicdriver, combograph, plus one extension-plugin adapter). `apply` with `dry_run:true` returns a per-field report — field writes, silent drops, clamps, and errors — before anything is persisted. Optional/conditional adapters degrade cleanly when their plugin is absent.

### Reflection Intelligence (`decision` 5 + `risk` 5 + `cppreflect` 6 + `network` 4 + `pipeline` 2 + `reflect` 1 + 5 cross-namespace audits)
**Added in 0.17.0** (the `reflect` namespace followed in 0.19.0). A deterministic reflection layer that lets your AI answer "why did we do it this way?", "which files are risky to change?", "what assets depend on this C++ class?", "is this OnRep handler actually wired up?", and "is this PR safe to merge?". Zero LLM calls, zero embeddings, zero network — all SQLite + UHT artefact reading + regex sweeps + git mining on top of new tables added to `EngineSource.db`.

- **`decision_query`** harvests architectural decision records from `Docs/`, plans, `CHANGELOG.md`, and `.claude/rules/` via three heuristic tiers (YAML frontmatter 0.90, ADR-style headers 0.85, header + `because`/`rationale`/`evidence` paragraph 0.65). Actions: `list_decisions`, `get_decision`, `list_stale`, `find_supersession_chain`, `find_referent_decisions`.
- **`risk_query`** mines per-file churn, co-change pairs, blended hotspot scores (`0.6 * churn + 0.4 * loc`), release-window thresholds, and conditional gates (`#if WITH_*` macros + `bHas*` 3-location probes + `MONOLITH_RELEASE_BUILD` bypasses) from up to six nested git repos. Plus `source_query("audit_module_dep_reality")` catches the LNK2019 bug class where UPROPERTY references a foreign-module type whose owning module is missing from `Build.cs`.
- **`cppreflect_query`** reads UHT artefacts (`Intermediate/Build/.../Inc/<Module>/UHT/*.gen.cpp`) and cross-joins with `IAssetRegistry::GetDependencies`. Lets you walk UCLASSes, UPROPERTYs, UFUNCTIONs, UINTERFACEs and their implementations, plus `cpp_asset_edges` mapping assets to the C++ classes they depend on. The indexers scan your project plugins by default — `bIndexProjectPluginReflection` default-on — with enabled marketplace plugins gated behind `bIndexMarketplacePluginReflection` and Epic engine built-ins excluded.
- **`network_query`** inspects UE 5.7 replication: replicated classes, RPC functions, OnRep handlers paired with their properties, plus an audit for `ReplicatedUsing=OnRep_X` declarations whose `OnRep_X` function doesn't exist. `list_replicated_classes` captures bare `UPROPERTY(Replicated)` + `DOREPLIFETIME` (via `CPF_Net`) in addition to `ReplicatedUsing` — verified end-to-end. `list_rpc_functions` switched to specifier-based detection (`EFunctionFlags`) and, with the plugin scan-scope expansion, now covers project plugins by default — so it returns the project's actual RPCs (verified E2E against the project's project-plugin RPCs) rather than coming back empty.
- **`pipeline_query`** ships two read-only composer actions — `pr_review` (fans out risk + decision + module-dep audit + CDO drift per changed file) and `release_readiness` (status + stale decisions + release-window hotspots + sentinel-list audit + CHANGELOG completeness audit).
- **`reflect_query`** ships one WRITE/maintenance action — `rebuild_reflection_index` (no params) — a project-only force-rebuild of the RI reflection tables. It exists because after an indexer code change there's no other clean repopulation trigger. Idempotent, non-destructive.
- **Cross-namespace audits:** `material_query("audit_orphan_materials")`, `niagara_query("audit_cross_asset_refs")`, `blueprint_query("audit_cdo_drift")`, `project_query("audit_orphan_assets")` — owned by the reflection module but registered onto their host namespace for caller ergonomics.

Full deferral notes (Phase 3b tree-sitter native-tag tracking, Phase 4b tag-graph + animation thread-safety) live in [[Changelog]].

### AI onboarding guide (`monolith_guide`)
Also new in 0.15.0. `monolith_guide()` serves a section-keyed editorial guide *for your AI agent* — not human-only docs. Six sections: `onboarding` (a first-session script), `recipes` (worked cross-namespace workflows), `decisions` (X-vs-Y matrices for "which action do I use?"), `errors` (error-to-recovery maps), `skills_map` (pointers to the bundled skills), and `gotchas` (Monolith-specific traps). Call it with no args for the full index, or `monolith_guide(section="recipes")` to pull a single section and bound context cost. It's hand-authored markdown plus a **live registry overlay**, so the action counts and version it reports always match your running build. Built for users with no project `CLAUDE.md`, private skills, or agent registry — point your AI at it and it self-onboards. Offline parity via `monolith_query.exe monolith guide`.

## Architecture

Monolith uses a **namespace dispatch pattern**. Instead of registering ~1,500+ individual MCP tools (which would overwhelm any AI client's context window), it exposes a small set of namespace-dispatch tools. Each domain has a single `{namespace}_query(action, params)` entry point. Call `monolith_discover()` to see everything available — it lists actions with a one-line description each (terse by default). When your AI needs an action's full param schema, it fetches just that one with `describe_query("action_schema")`, or passes `detail=true` to `monolith_discover` for the schemas inline. New AI clients can also call `monolith_guide()` to self-onboard.

The plugin runs as an HTTP server inside the Unreal Editor (default port 9316). No sidecar process, no bridge, no relay. The MCP connection is direct — your AI client talks to the editor.

Two standalone C++ executables (`monolith_proxy.exe` and `monolith_query.exe`) complement the editor plugin. The proxy keeps MCP sessions alive across editor restarts with zero Python dependency. The query tool provides instant offline access to the source and project databases without loading the UE runtime.

Every action is self-documenting. Parameter schemas are embedded in `tools/list` at session start, so clients with tool schema support get full documentation automatically.

## About This Project

Monolith is a solo hobby project. It started as a simple source indexer so I could look up UE C++ APIs from Claude Code while working on a personal project. That turned into a Blueprint inspector, then a material editor, then a Niagara tool — and eventually it made more sense to consolidate everything into one plugin rather than juggle half a dozen separate MCP servers.

A lot of the features were added specifically to help newer developers and Blueprint-only users get more out of AI tooling with Unreal Engine. Most of the actions were originally built and proven in Python MCP servers before being ported to native C++ — so the functionality is solid, it's just the C++ side that's catching up on test coverage.

I work full-time, so this gets built in whatever spare time I can find. All features work — it's just a matter of time before each one gets formally tested and documented in the new C++ codebase. If something's rough around the edges, that's why. Bug reports are always welcome, and I'll get to them as fast as I can.

If you find Monolith useful and want to help keep it going, [sponsorships are appreciated](https://github.com/sponsors/tumourlove). No pressure — just nice to know people are getting value out of it.
